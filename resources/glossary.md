## 1. LLM Architecture & Fundamentals

- **Token**: The discrete numeric unit processed by a language model, representing a character, subword, or word (~0.75 English words). Tokens dictate API billing, memory allocation, and context limits; under-tokenized non-English languages suffer a 3–5x cost and latency penalty.  
  → See [02-tokenization.md](../01-llm-fundamentals/02-tokenization.md)

- **Tokenization**: The deterministic parsing of raw text into integer token IDs using fixed vocabulary tables generated by algorithms like Byte-Pair Encoding. Mismatches between input whitespace, Unicode sequences, and tokenizer vocabulary lead to silent degradation in structured output and arithmetic tasks.  
  → See [02-tokenization.md](../01-llm-fundamentals/02-tokenization.md)

- **Byte-Pair Encoding (BPE)**: A subword tokenization algorithm that iteratively merges the most frequent pairs of bytes/characters in a training corpus into unified vocabulary tokens. Because token boundaries are statistical rather than linguistic, BPE causes models to fail basic character-manipulation tasks like word reversal without explicit scratchpads.  
  → See [02-tokenization.md](../01-llm-fundamentals/02-tokenization.md)

- **Embedding (Internal vs External)**: Internal embeddings are dynamic hidden-state vectors produced by intermediate transformer layers representing contextual token representations during inference. External embeddings are static, fixed-dimension vectors generated by dedicated embedding models (e.g., `text-embedding-3-large`) strictly for offline similarity indexing in vector databases.  
  → See [03-embeddings.md](../01-llm-fundamentals/03-embeddings.md)

- **Positional Encoding**: Mathematical vectors added to token embeddings to inject sequence order into permutation-invariant self-attention operations. Naive absolute sinusoidal encodings fail when sequences exceed the maximum training length, causing catastrophic degradation in out-of-distribution context lengths.  
  → See [04-positional-encoding.md](../01-llm-fundamentals/04-positional-encoding.md)

- **RoPE (Rotary Position Embedding)**: A relative positional encoding method that rotates query and key vectors in 2D coordinate planes using complex numbers, capturing positional distance directly via inner products. RoPE enables effective context window extension via position interpolation techniques (e.g., YaRN) with minimal fine-tuning.  
  → See [04-positional-encoding.md](../01-llm-fundamentals/04-positional-encoding.md)

- **ALiBi (Attention with Linear Biases)**: A positional encoding scheme that penalizes query-key attention scores linearly based on their token distance without adding positional vectors to embeddings. ALiBi provides exceptional length extrapolation during inference, allowing models trained on 2k sequences to process 8k+ sequences without finetuning.  
  → See [04-positional-encoding.md](../01-llm-fundamentals/04-positional-encoding.md)

- **Transformer**: A neural architecture relying entirely on multi-head attention and feed-forward networks to model long-range sequence dependencies in parallel without recurrence. In production, its pure quadratic memory complexity ($O(N^2)$) requires optimizations like FlashAttention to avoid out-of-memory errors on long prompts.  
  → See [05-transformer-architecture.md](../01-llm-fundamentals/05-transformer-architecture.md)

- **Encoder**: The transformer sub-network that computes bidirectional, contextual representations across all input tokens simultaneously (e.g., BERT). Encoders cannot autoregressively generate free-form text efficiently but form the backbone of high-accuracy embedding and classification models.  
  → See [05-transformer-architecture.md](../01-llm-fundamentals/05-transformer-architecture.md)

- **Decoder**: The autoregressive transformer sub-network that applies causal masking to generate tokens sequentially by attending only to preceding tokens (e.g., GPT, Llama). Modern LLM production systems predominantly use decoder-only architectures due to their unified capacity for zero-shot generalization, reasoning, and instruction following.  
  → See [05-transformer-architecture.md](../01-llm-fundamentals/05-transformer-architecture.md)

- **Self-Attention**: The mechanism allowing each token in a sequence to calculate dynamic relevance scores against every other token via scaled dot-products. This operation incurs an $O(N^2)$ compute and memory footprint, making raw self-attention the primary latency bottleneck during prompt processing (prefill).  
  → See [06-self-attention.md](../01-llm-fundamentals/06-self-attention.md)

- **Multi-Head Attention (MHA)**: An attention architecture that projects Queries, Keys, and Values into multiple independent subspace projections ("heads") to attend to disparate semantic features simultaneously. Running multiple separate Key-Value heads per attention layer creates massive KV cache memory footprints during high-concurrency inference, spurring architectures like Multi-Query (MQA) and Grouped-Query Attention (GQA).  
  → See [06-self-attention.md](../01-llm-fundamentals/06-self-attention.md)

- **QKV (Query, Key, Value)**: The three projection vectors derived from input token embeddings that execute attention: Query represents what a token seeks, Key represents what a token contains, and Value represents the retrieved semantic content. Attention weight is computed as $\text{Softmax}(QK^T / \sqrt{d_k})V$.  
  → See [06-self-attention.md](../01-llm-fundamentals/06-self-attention.md)

- **Feed-Forward Network (FFN)**: The multi-layer perceptron following self-attention in each transformer block that processes tokens position-wise and holds the vast majority of static factual parameters. The FFN accounts for approximately two-thirds of total model parameters (excluding the embedding layer) and floating-point operations in standard dense models.  
  → See [07-feed-forward-network.md](../01-llm-fundamentals/07-feed-forward-network.md)

- **Mixture of Experts (MoE)**: An architecture replacing dense FFN layers with multiple sparse "expert" sub-networks, routing each token to only top-$k$ experts (e.g., 2 of 8 in Mixtral). MoE dramatically cuts inference FLOPs per token while demanding the full VRAM capacity required to hold all dormant experts in memory.  
  → See [07-feed-forward-network.md](../01-llm-fundamentals/07-feed-forward-network.md)

- **Context Window**: The maximum sequence length (input prompt plus generated completion) that a model can process in a single forward pass without truncating attention. Exceeding or packing context windows triggers the "Lost-in-the-Middle" degradation, where retrieval accuracy drops sharply for facts located far from sequence extremes.  
  → See [08-context-window.md](../01-llm-fundamentals/08-context-window.md)

- **KV Cache**: An inference memory optimization that stores the computed Key and Value tensors of previous tokens in GPU VRAM to avoid recomputing them during autoregressive decoding. While eliminating quadratic recomputation during generation, the KV cache grows dynamically ($2 \times \text{layers} \times \text{heads} \times d_{\text{head}} \times \text{seq\_len} \times \text{batch}$), making it the primary limiter of maximum concurrent inference throughput.  
  → See [11-inference-vs-training.md](../01-llm-fundamentals/11-inference-vs-training.md)

- **FlashAttention**: An exact attention algorithm that reorganizes the attention computation into GPU SRAM tiles, minimizing slow HBM (High Bandwidth Memory) read/writes. FlashAttention reduces memory footprint from $O(N^2)$ to $O(N)$ and yields 2–4x speedups without any numerical approximation.  
  → See [06-self-attention.md](../01-llm-fundamentals/06-self-attention.md)

## 2. Sampling & Inference Mechanics

- **Temperature**: A scalar hyperparameter that scales pre-softmax logits ($\text{logits} / T$) to flatten ($T > 1$) or sharpen ($T < 1$) the next-token probability distribution. Setting temperature to 0 forces greedy decoding (deterministic argmax), but does not guarantee reproducible outputs across distributed inference engines due to floating-point nondeterminism.  
  → See [09-output-head-and-sampling.md](../01-llm-fundamentals/09-output-head-and-sampling.md)

- **Top-p (Nucleus Sampling)**: A dynamic truncation method that samples exclusively from the smallest cumulative subset of top tokens whose combined probability mass exceeds threshold $p$ (e.g., 0.9). Top-p dynamically expands the candidate pool for ambiguous tokens and shrinks it for obvious completions, preventing low-probability gibberish far better than static temperature alone.  
  → See [09-output-head-and-sampling.md](../01-llm-fundamentals/09-output-head-and-sampling.md)

- **Top-k Sampling**: A static filtering technique that constrains next-token sampling strictly to the $k$ highest-probability tokens regardless of their relative probability distribution. Setting $k$ too low eliminates valid context-specific terminology, while setting $k$ too high admits nonsensical tail tokens when generating deterministic code or JSON.  
  → See [09-output-head-and-sampling.md](../01-llm-fundamentals/09-output-head-and-sampling.md)

- **Beam Search**: A heuristic search algorithm that maintains the top-$B$ most probable candidate sequences across decoding steps instead of greedily picking one token at a time. While valuable for short, structured translation and summarization, beam search introduces severe latency overhead, high memory usage, and repetitive outputs in long-form open generation.  
  → See [09-output-head-and-sampling.md](../01-llm-fundamentals/09-output-head-and-sampling.md)

## 3. Training & Alignment

- **Pre-training**: The self-supervised phase where an initialized transformer predicts masked or next tokens across trillions of web, book, and code tokens to learn general world representations. Pre-training consumes over 98% of total training compute and produces base models that generate text completions rather than helpful conversational responses.  
  → See [10-training-pipeline.md](../01-llm-fundamentals/10-training-pipeline.md)

- **Supervised Fine-Tuning (SFT)**: The training phase that conditions a pre-trained base model on high-quality demonstration pairs (instruction and target response) using cross-entropy loss. SFT teaches conversational style, role obedience, and response schema compliance, but cannot reliably teach net-new factual knowledge without severe hallucination risks.  
  → See [04-fine-tuning/02-supervised-fine-tuning.md](../04-fine-tuning/02-supervised-fine-tuning.md)

- **Reinforcement Learning from Human Feedback (RLHF)**: A post-training alignment process that trains a reward model on paired human preferences, then optimizes the policy model via PPO (Proximal Policy Optimization) to maximize reward while penalizing divergence from the SFT model. RLHF aligns model safety and helpfulness, but introduces complex multi-model training instability and inference verbosity.  
  → See [04-fine-tuning/04-alignment/01-rlhf.md](../04-fine-tuning/04-alignment/01-rlhf.md)

- **Direct Preference Optimization (DPO)**: A stable, reward-model-free alignment algorithm that derives an analytical closed-form objective to directly optimize the policy model on paired binary preferences (chosen vs rejected). DPO eliminates the operational overhead and collapse vulnerability of running separate PPO actor, critic, and reward models during alignment.  
  → See [04-fine-tuning/04-alignment/02-dpo.md](../04-fine-tuning/04-alignment/02-dpo.md)

- **RLAIF (Reinforcement Learning from AI Feedback)**: An alignment framework (popularized by Anthropic's Constitutional AI) that substitutes human annotators with frontier LLMs evaluating outputs against explicit constitutional rules. RLAIF slashes alignment costs by orders of magnitude while delivering safety and preference benchmarks comparable to human-labeled RLHF.  
  → See [04-fine-tuning/04-alignment/03-rlaif.md](../04-fine-tuning/04-alignment/03-rlaif.md)

- **Catastrophic Forgetting**: The destructive loss of previously learned capabilities (e.g., common-sense reasoning, coding, math) when fine-tuning a model aggressively on a narrow domain dataset. Prevented in production by mixing 10–20% of general pre-training data into fine-tuning corpora or freezing base weights via PEFT.  
  → See [04-fine-tuning/01-fine-tuning-overview.md](../04-fine-tuning/01-fine-tuning-overview.md)

## 4. Model Behaviors & Failure Modes

- **Hallucination**: The generation of factually incorrect, ungrounded, or internally contradictory assertions with high statistical confidence. Hallucinations stem from the model's fundamental objective (minimizing cross-entropy loss over token probability distributions) rather than retrieving verified knowledge.  
  → See [12-hallucination.md](../01-llm-fundamentals/12-hallucination.md)

- **Grounding**: The architectural practice of strictly conditioning LLM generation on verified external reference data supplied within the prompt context. Un-grounded systems drift over time; production systems enforce grounding via system prompt constraints, extraction boundaries, and citations.  
  → See [02-rag/README.md](../02-rag/README.md)

- **Faithfulness**: The degree to which an LLM's generated response can be directly inferred from and justified by the provided context documents without uncorroborated extrapolations. Faithfulness is the primary metric used to detect hallucinations in RAG and question-answering evaluation pipelines.  
  → See [05-evaluation/README.md](../05-evaluation/README.md)

- **Sycophancy**: The model tendency to agree with user assertions, validate biased premises, or reverse correct statements when challenged by the user, regardless of factual accuracy. Sycophancy is an artifact of RLHF reward modeling where human evaluators systematically rate agreeable responses higher than corrective ones.  
  → See [13-reasoning-failures.md](../01-llm-fundamentals/13-reasoning-failures.md)

- **Recency Bias**: The model's vulnerability to over-weighting tokens placed at the very end of a prompt context while under-attending to information in the middle. In production pipelines, critical system instructions and formatting constraints should be placed at the system prompt and repeated near the tail of the payload.  
  → See [08-context-window.md](../01-llm-fundamentals/08-context-window.md)

- **Lost-in-the-Middle**: The empirical degradation in LLM retrieval performance where facts situated in the middle of long prompt contexts are retrieved with significantly lower accuracy than facts at the immediate beginning or end. Mitigated by context compression, reranking top chunks to prompt boundaries, or prompt structuring.  
  → See [08-context-window.md](../01-llm-fundamentals/08-context-window.md)

## 5. Retrieval-Augmented Generation (RAG)

- **RAG (Retrieval-Augmented Generation)**: An architectural pattern that retrieves relevant external documents based on a user query and passes them as grounding context to an LLM at inference time. RAG decouples model knowledge from parametric weights, enabling real-time factual updates, source attribution, and access-control enforcement.  
  → See [02-rag/README.md](../02-rag/README.md)

- **Indexing Pipeline**: The asynchronous, offline ETL workflow that extracts raw documents, normalizes text, splits content into chunks, generates vector embeddings, and stores vectors with metadata in an index. Flaws in the indexing pipeline set a hard upper bound on the maximum retrieval quality achievable during inference.  
  → See [02-rag/README.md](../02-rag/README.md)

- **Query Pipeline**: The synchronous runtime workflow that accepts a user prompt, optionally rewrites or expands it, queries retrieval indices, reranks candidate passages, constructs the final prompt, and streams model output. Query pipeline latency directly dictates end-to-end user wait time.  
  → See [02-rag/README.md](../02-rag/README.md)

- **Chunking**: The process of breaking large text corpora into discrete segment lengths suitable for embedding models and context injection. Chunks that are too small lose narrative context; chunks that are too large dilute embedding vector sharpness and pollute LLM prompts with irrelevant text.  
  → See [03-chunking-strategies.md](../02-rag/02-data-ingestion/03-chunking-strategies.md)

- **Semantic Chunking**: An adaptive chunking technique that computes similarity scores between consecutive sentences and places chunk boundaries only where semantic distance crosses an empirical threshold. Semantic chunking prevents arbitrary midpoint sentence splits at the cost of running embedding inference across every raw sentence during data ingestion.  
  → See [03-chunking-strategies.md](../02-rag/02-data-ingestion/03-chunking-strategies.md)

- **Parent-Child Chunking**: A retrieval strategy that splits documents into small child chunks (e.g., 128 tokens) for fine-grained vector similarity search, but retrieves and passes their surrounding parent chunks (e.g., 1024 tokens) to the LLM. This decouples retrieval precision from synthesis context richness.  
  → See [02-rag/README.md](../02-rag/README.md)

- **HyDE (Hypothetical Document Embeddings)**: A query transformation technique where an LLM generates a fictitious answer to a user query, which is then embedded to retrieve real documents from the vector database. HyDE maps queries from question-space to document-space, overcoming keyword mismatches at the expense of an extra LLM call.  
  → See [02-rag/05-retrieval/](../02-rag/05-retrieval/)

- **Multi-Query Expansion**: A technique where an LLM rewrites a single user prompt into 3–5 distinct semantic variations, retrieves candidate chunks for each variation in parallel, and merges the deduplicated results. Multi-Query overcomes poor user phrasing and uneven embedding space coverage, though it multiplies vector index load.  
  → See [02-rag/05-retrieval/](../02-rag/05-retrieval/)

- **Step-Back Prompting**: A prompt transformation that prompts the LLM to formulate a higher-level, abstract concept question derived from the specific input query to retrieve background principles. Retrieving both step-back grounding facts and specific query details prevents the LLM from hallucinating foundational domain concepts.  
  → See [02-rag/05-retrieval/](../02-rag/05-retrieval/)

- **Semantic Cache**: An inference cache that evaluates incoming query embeddings against previously answered queries using cosine similarity, returning cached responses if similarity exceeds a strict threshold (e.g., 0.95). Semantic caching cuts token spend and latency to near zero for repeated queries, but risks returning stale or invalid data if invalidated improperly.  
  → See [02-rag/07-advanced-rag/](../02-rag/07-advanced-rag/)

- **Agentic RAG**: A dynamic retrieval architecture where an autonomous LLM loop inspects query complexity, selects distinct data sources, critiques intermediate search results, and reformulates follow-up queries until confident. Unlike linear standard RAG, Agentic RAG trades latency and cost for significantly higher retrieval accuracy on multi-hop questions.  
  → See [07-ai-systems-design/02-architectural-patterns/03-agentic-rag.md](../07-ai-systems-design/02-architectural-patterns/03-agentic-rag.md)

- **GraphRAG**: A retrieval architecture that constructs a knowledge graph of extracted entities and relationships across source documents, using graph traversals and community summaries alongside vector search. GraphRAG resolves complex global thematic questions ("What are the main themes across all contracts?") where standard vector RAG catastrophically fails.  
  → See [02-rag/07-advanced-rag/](../02-rag/07-advanced-rag/)

## 6. Search, Vector Indexing & Retrieval

- **Vector Database**: A specialized database optimized for storing, indexing, and executing low-latency nearest-neighbor searches over multi-dimensional embedding vectors alongside metadata filters. Unlike relational databases, vector DB queries return approximate similarity matches rather than exact deterministic records.  
  → See [02-rag/README.md](../02-rag/README.md)

- **ANN (Approximate Nearest Neighbors)**: A class of search algorithms that sacrifices a small amount of recall accuracy (tunable via index parameters) to find nearest vector neighbors orders of magnitude faster than brute-force $O(N)$ exhaustive scans. ANN indexes are required to achieve sub-50ms retrieval latencies across corpora with millions of vectors.  
  → See [02-semantic-search.md](../02-rag/05-retrieval/02-semantic-search.md)

- **HNSW (Hierarchical Navigable Small World)**: A graph-based ANN index algorithm that structures vectors into multi-layer geometric graphs, executing fast logarithmic searches from sparse top layers down to dense bottom layers. HNSW delivers the highest query throughput and recall in production, but requires significant RAM to store graph edge pointers.  
  → See [02-semantic-search.md](../02-rag/05-retrieval/02-semantic-search.md)

- **IVF (Inverted File Index)**: A cluster-based ANN index that partitions vector space into Voronoi cells using k-means, querying only the centroids nearest the search vector. IVF has a substantially smaller memory footprint than HNSW, but exhibits lower recall and requires periodic re-clustering as new data arrives.  
  → See [02-rag/README.md](../02-rag/README.md)

- **BM25**: A probabilistic sparse keyword search ranking algorithm that scores document relevance based on term frequency (TF) and inverse document frequency (IDF), normalized by document length. BM25 excels at exact keyword, alphanumeric SKU, and proper noun matching where dense embedding search fails.  
  → See [02-rag/05-retrieval/](../02-rag/05-retrieval/)

- **Hybrid Search**: The combination of dense semantic retrieval (embeddings) and sparse keyword retrieval (BM25) executed concurrently on a single query. Hybrid search prevents semantic search blind spots on acronyms, part numbers, and entity names while retaining natural language conceptual matching.  
  → See [02-rag/05-retrieval/](../02-rag/05-retrieval/)

- **RRF (Reciprocal Rank Fusion)**: A model-free algorithm that merges ranked lists from disparate retrieval methods (e.g., BM25 and vector search) by summing reciprocal ranks: $\text{score} = \sum 1 / (k + \text{rank})$. RRF produces calibrated rank lists without requiring normalization across incompatible similarity score distributions.  
  → See [02-rag/05-retrieval/](../02-rag/05-retrieval/)

- **Bi-Encoder**: An embedding architecture that encodes queries and documents into isolated vector representations independently via separate forward passes. Bi-encoders enable lightning-fast vector database lookups via dot products, but fail to model fine-grained token-level interactions between query and document.  
  → See [02-rag/05-retrieval/](../02-rag/05-retrieval/)

- **Cross-Encoder**: A model architecture that concatenates query and candidate document tokens into a single input sequence, computing full bidirectional attention across all query-document token pairs simultaneously. Cross-encoders achieve dramatically superior ranking precision compared to bi-encoders, but are too computationally slow to run across entire corpus databases.  
  → See [02-rag/05-retrieval/](../02-rag/05-retrieval/)

- **Reranking**: A two-stage retrieval pattern where a fast bi-encoder or BM25 fetches top-$N$ candidates (e.g., 50), and a computationally heavier cross-encoder rescores and sorts them to extract top-$K$ chunks (e.g., 5). Reranking represents the single most cost-effective lever for boosting production RAG retrieval precision.  
  → See [02-rag/05-retrieval/](../02-rag/05-retrieval/)

## 7. Agentic AI & Orchestration

- **AI Agent**: An autonomous system where an LLM dynamically controls an iterative loop of reasoning, environment observation, tool execution, and self-correction to achieve a user objective. Agents trade determinism and latency for the capability to solve unstructured, multi-step tasks without hardcoded if/else pipelines.  
  → See [01-agents-overview.md](../03-agentic-ai/01-agents-overview.md)

- **ReAct (Reason + Act)**: An agent design pattern that interleaves natural language reasoning ("Thought") with concrete tool calls ("Action") and environment feedback ("Observation"). Explicitly articulating reasoning traces dramatically reduces hallucinated tool calls and improves planning over zero-shot function calling.  
  → See [02-react-pattern.md](../03-agentic-ai/02-react-pattern.md)

- **Tool Calling (Function Calling)**: The structured mechanism by which an LLM detects when an external operation is required, generates a valid JSON payload matching a declared schema, and pauses generation until the runtime executes the function and injects the output. Production tool calls require schema validation (e.g., Pydantic) and strict timeout guards to prevent application crashes.  
  → See [04-multi-agent-frameworks.md](../03-agentic-ai/06-multi-agent-systems/04-multi-agent-frameworks.md)

- **MCP (Model Context Protocol)**: An open standardized protocol created by Anthropic that decouples LLM applications from data sources and tools via client-server architecture. MCP eliminates custom tool integration boilerplate by allowing models to securely discover and invoke tools across standardized local or remote servers.  
  → See [04-multi-agent-frameworks.md](../03-agentic-ai/06-multi-agent-systems/04-multi-agent-frameworks.md)

- **Working Memory**: The short-term, in-context state maintained during an active agent session, consisting of the scratchpad, current tool outputs, and execution graph variables. Working memory is bounded by the context window and must be actively pruned or summarized to prevent context overflow.  
  → See [04-multi-agent-frameworks.md](../03-agentic-ai/06-multi-agent-systems/04-multi-agent-frameworks.md)

- **Episodic Memory**: The persistent historical record of an agent's past user interactions, successful trajectories, and past failures across previous sessions. Stored in vector indices or document stores, episodic memory allows agents to adapt to recurring user patterns and avoid repeating historical mistakes.  
  → See [04-multi-agent-frameworks.md](../03-agentic-ai/06-multi-agent-systems/04-multi-agent-frameworks.md)

- **Semantic Memory**: The persistent, structured knowledge base of factual concepts, domain rules, and world models available to an agent. Implemented via vector databases or relational knowledge graphs, semantic memory gives the agent access to facts beyond its parametric weights.  
  → See [04-multi-agent-frameworks.md](../03-agentic-ai/06-multi-agent-systems/04-multi-agent-frameworks.md)

- **Procedural Memory**: The persistent repository of operational execution guidelines, standard workflows, and specialized tool-calling playbooks that dictate how an agent executes tasks. In modern systems, procedural memory is embedded in system prompt templates, few-shot demonstration catalogs, and fine-tuned policy weights.  
  → See [04-multi-agent-frameworks.md](../03-agentic-ai/06-multi-agent-systems/04-multi-agent-frameworks.md)

- **Orchestrator**: The central supervisor agent or state machine responsible for breaking a high-level goal into discrete tasks, delegating them to worker agents, and aggregating the final output. In production systems, orchestrator logic should be heavily constrained using deterministic state machines rather than open-ended autonomous agents.  
  → See [02-orchestrator-worker.md](../03-agentic-ai/06-multi-agent-systems/02-orchestrator-worker.md)

- **Worker Agent**: A specialized, narrow-scope agent configured with a small set of domain tools (e.g., SQL queries, document extraction) that executes specific sub-tasks delegated by the orchestrator. Isolating tools into discrete workers avoids tool-selection confusion and prompt bloat.  
  → See [07-ai-systems-design/README.md](../07-ai-systems-design/README.md)

- **LangGraph**: A cyclic orchestration framework from LangChain that models agent workflows as stateful computational graphs containing nodes, conditional edges, and explicit checkpoints. LangGraph enables production-grade human-in-the-loop interventions, time-travel debugging, and multi-agent fault recovery.  
  → See [04-multi-agent-frameworks.md](../03-agentic-ai/06-multi-agent-systems/04-multi-agent-frameworks.md)

- **CrewAI**: A role-based multi-agent orchestration framework designed around autonomous collaborative "crews" with defined personas, goals, and inter-agent delegation patterns. CrewAI speeds prototyping for collaborative problem-solving, but can be prone to runaway costs if inter-agent loops are unconstrained.  
  → See [04-multi-agent-frameworks.md](../03-agentic-ai/06-multi-agent-systems/04-multi-agent-frameworks.md)

- **AutoGen**: Microsoft's multi-agent conversational framework enabling complex workflows via multi-turn conversations between customizable, tool-enabled agents and human participants. AutoGen provides flexible group-chat management, but requires strict termination conditions to avoid infinite circular debate loops.  
  → See [04-multi-agent-frameworks.md](../03-agentic-ai/06-multi-agent-systems/04-multi-agent-frameworks.md)

- **Prompt Chaining**: A deterministic architectural pattern that decomposes a complex task into a sequential series of explicit LLM calls, where each step's output is validated before feeding into the next prompt. Prompt chaining provides high reliability and debuggability without the latency and unpredictability of autonomous agents.  
  → See [07-ai-systems-design/02-architectural-patterns/01-prompt-chaining.md](../07-ai-systems-design/02-architectural-patterns/01-prompt-chaining.md)

## 8. Fine-Tuning & Parameter Adaptation

- **Fine-Tuning**: The process of taking a pre-trained base model and further training its weights on a curated domain-specific dataset using gradient descent. Fine-tuning modifies a model's voice, formatting, reasoning style, or behavioral rules, but is inefficient and unreliable for teaching volatile facts.  
  → See [01-fine-tuning-overview.md](../04-fine-tuning/01-fine-tuning-overview.md)

- **PEFT (Parameter-Efficient Fine-Tuning)**: A suite of techniques that freezes the vast majority of pre-trained model weights and updates only a tiny fraction (<1%) of added parameters. PEFT slashes GPU memory requirements during training and prevents catastrophic forgetting of base capabilities.  
  → See [03-peft-and-lora.md](../04-fine-tuning/03-peft-and-lora.md)

- **LoRA (Low-Rank Adaptation)**: A PEFT technique that decomposes weight updates into two low-rank matrices ($W + \Delta W = W + B \times A$), freezing original weights and updating only low-rank matrices during backpropagation. LoRA reduces trainable parameters by 99% while enabling zero-latency inference merges and hot-swappable task adapters on a single base model.  
  → See [03-peft-and-lora.md](../04-fine-tuning/03-peft-and-lora.md)

- **QLoRA (Quantized Low-Rank Adaptation)**: An extension of LoRA that quantizes the base transformer weights to 4-bit NormalFloat (NF4) precision and backpropagates gradients through frozen quantized weights into 16-bit LoRA adapters. QLoRA enables fine-tuning a 65B parameter model on a single GPU with 48GB VRAM with virtually zero performance loss.  
  → See [03-peft-and-lora.md](../04-fine-tuning/03-peft-and-lora.md)

- **Quantization**: The compression process of mapping model weights and/or activations from high-precision floating-point formats (FP16/BF16) to lower-bit representations (INT8, INT4, FP4). Quantization cuts memory footprints and bandwidth demands by 50–75%, directly increasing batch capacity and reducing GPU hosting infrastructure costs.  
  → See [07-model-quantization.md](../06-production/02-cost-optimization/07-model-quantization.md)

- **GPTQ**: A post-training quantization algorithm that quantizes weight matrices to 4-bit or 3-bit using second-order Taylor expansions to minimize layer-wise output errors. GPTQ offers high compression and fast decoding for GPU-bound inference, but cannot be easily adapted during runtime.  
  → See [07-model-quantization.md](../06-production/02-cost-optimization/07-model-quantization.md)

- **AWQ (Activation-aware Weight Quantization)**: An advanced post-training quantization method that protects the top 1% of salient weights corresponding to large activation magnitudes before quantizing the remaining weights to 4-bit. AWQ consistently outperforms GPTQ across reasoning and perplexity benchmarks without significant throughput penalties.  
  → See [07-model-quantization.md](../06-production/02-cost-optimization/07-model-quantization.md)

## 9. Evaluation & Observability

- **BLEU (Bilingual Evaluation Understudy)**: An n-gram precision metric that measures the lexical overlap between generated text and human reference texts. BLEU penalizes valid paraphrasing, synonyms, and creative structuring, rendering it unreliable for evaluating modern open-ended LLM outputs.  
  → See [05-evaluation/README.md](../05-evaluation/README.md)

- **ROUGE (Recall-Oriented Understudy for Gisting Evaluation)**: An n-gram recall metric primarily used to assess summarization overlap against target references. Similar to BLEU, ROUGE cannot detect factual hallucinations or evaluate qualitative reasoning, making it insufficient as a primary production gate.  
  → See [05-evaluation/README.md](../05-evaluation/README.md)

- **BERTScore**: An evaluation metric that computes token-level semantic similarity using contextual embedding cosine scores rather than exact surface token matches. BERTScore captures paraphrasing much better than BLEU/ROUGE, but struggles to catch subtle factual inversions (e.g., "not guilty" vs "guilty").  
  → See [01-reference-based-metrics.md](../05-evaluation/02-llm-evaluation/01-reference-based-metrics.md)

- **LLM-as-a-Judge**: An evaluation methodology using an advanced frontier model (e.g., GPT-4o) guided by detailed rubrics to score generation quality, faithfulness, and style. While scalable and well-correlated with human judgment, it introduces position bias, verbosity bias, self-enhancement bias, and high evaluation token costs.  
  → See [05-evaluation/README.md](../05-evaluation/README.md)

- **G-Eval**: A specialized LLM-as-a-Judge framework that uses chain-of-thought prompting to auto-generate task-specific evaluation steps and computes a weighted score over output probability distributions. G-Eval significantly improves human evaluation correlation and metric stability compared to naive zero-shot scoring prompts.  
  → See [05-evaluation/README.md](../05-evaluation/README.md)

- **RAGAS (Retrieval Augmented Generation Assessment)**: An open-source evaluation framework providing reference-free metrics tailored for RAG pipelines, including Faithfulness, Answer Relevance, Context Precision, and Context Recall. RAGAS isolates retrieval errors from generation errors, pinpointing exact pipeline bottlenecks.  
  → See [05-evaluation/README.md](../05-evaluation/README.md)

- **Faithfulness Score**: A metric defined in frameworks like RAGAS that computes the ratio of generated claims verifiable in the retrieved context to total generated claims: $\text{Verifiable Claims} / \text{Total Claims}$. A drop in faithfulness indicates generation hallucinations independent of retrieval quality.  
  → See [05-evaluation/README.md](../05-evaluation/README.md)

- **EDD (Eval-Driven Development)**: A software engineering paradigm for AI systems where quantitative evaluation benchmarks and golden test datasets are established *prior* to engineering prompts, retrieval parameters, or fine-tuning pipelines. EDD prevents teams from falling into the "vibes-based development trap" and enables regression-free continuous delivery.  
  → See [05-evaluation/README.md](../05-evaluation/README.md)

- **LangSmith**: A commercial observability, tracing, and evaluation platform developed by LangChain for monitoring LLM and agent execution graphs. LangSmith captures exact inputs, outputs, token latency, tool traces, and cost metrics at every node of a production pipeline.  
  → See [04-tools-and-platforms.md](../06-production/03-observability-and-monitoring/04-tools-and-platforms.md)

- **Langfuse**: An open-source, self-hostable LLM engineering platform providing distributed tracing, prompt management, cost tracking, and score evaluation. Langfuse enables enterprise teams to maintain full data sovereignty and privacy over their user telemetry and prompt logs.  
  → See [04-tools-and-platforms.md](../06-production/03-observability-and-monitoring/04-tools-and-platforms.md)

## 10. Production Serving, Optimization & Security

- **TTFT (Time to First Token)**: The latency duration spanning from when an inference engine receives a prompt to when it emits the very first output token, representing prompt processing (prefill) time. High TTFT degrades perceived interactivity in user-facing applications and is governed primarily by prompt token length and GPU compute capacity.  
  → See [06-production/README.md](../06-production/README.md)

- **TBT (Time Between Tokens)**: The inter-token latency (also known as TPOT - Time Per Output Token, or ITL - Inter-Token Latency) representing the time taken to decode each subsequent token after the initial token has been generated. TBT is governed by GPU memory bandwidth during KV cache reading and dictates the streaming reading speed experienced by the user.  
  → See [06-production/README.md](../06-production/README.md)

- **Continuous Batching**: An inference scheduling technique that dynamically inserts new incoming requests into running iteration loops as soon as earlier requests finish generating their end-of-sequence tokens. Continuous batching eliminates idle GPU compute bubbles caused by static batch padding, increasing inference engine throughput by 10–20x.  
  → See [06-production/02-cost-optimization/04-batching-strategies.md](../06-production/02-cost-optimization/04-batching-strategies.md)

- **PagedAttention**: An attention algorithm (pioneered by vLLM) inspired by virtual memory paging in operating systems that stores KV cache tensors in non-contiguous physical memory blocks. PagedAttention eliminates internal and external VRAM fragmentation, slashing wasted KV memory from over 60% to near 0%.  
  → See [06-production/02-cost-optimization/04-batching-strategies.md](../06-production/02-cost-optimization/04-batching-strategies.md)

- **Speculative Decoding**: An inference acceleration technique where a small, fast draft model generates candidate tokens speculatively, and a large target model validates them in parallel in a single forward pass. Speculative decoding speeds up inference by 2–3x with zero loss in target model output quality.  
  → See [06-production/02-cost-optimization/03-speculative-decoding.md](../06-production/02-cost-optimization/03-speculative-decoding.md)

- **Model Routing**: An architecture that dynamically classifies incoming query complexity, directing simple requests to cheap small models (e.g., Llama 3 8B or GPT-4o mini) and difficult multi-hop queries to frontier models (e.g., Claude 3.5 Sonnet). Model routing cuts API bills by up to 70% while maintaining frontier-level quality on difficult tasks.  
  → See [06-production/02-cost-optimization/02-model-routing.md](../06-production/02-cost-optimization/02-model-routing.md)

- **vLLM**: A high-throughput, low-latency open-source LLM serving engine featuring PagedAttention, continuous batching, chunked prefill, and native tensor parallelism. vLLM is the industry standard for self-hosting open-weight models in scalable production environments.  
  → See [02-self-hosted-inference.md](../06-production/04-deployment/02-self-hosted-inference.md)

- **TGI (Text Generation Inference)**: Hugging Face's production serving framework engineered for high-concurrency LLM deployment, supporting FlashAttention, continuous batching, and automated tensor parallelism across multi-GPU nodes.  
  → See [02-self-hosted-inference.md](../06-production/04-deployment/02-self-hosted-inference.md)

- **Prompt Injection**: A security attack where adversarial user input overrides developer system prompt instructions, forcing the model to perform unintended, malicious actions or reveal hidden prompt instructions. Direct injection exploits the fundamental architectural vulnerability that LLMs cannot strictly distinguish code/instructions from untrusted user data.  
  → See [06-production/01-guardrails-and-security/03-prompt-injection.md](../06-production/01-guardrails-and-security/03-prompt-injection.md)

- **Jailbreaking**: The engineering of adversarial prompts (e.g., roleplay scenarios, fictional framing, encoded ciphers) designed to bypass a model's safety alignment and trigger harmful or prohibited outputs. Robust production defenses require dual input/output guardrail classifiers rather than relying solely on the base model's alignment.  
  → See [06-production/01-guardrails-and-security/04-jailbreaking.md](../06-production/01-guardrails-and-security/04-jailbreaking.md)

- **PII (Personally Identifiable Information)**: Sensitive customer data (e.g., Social Security numbers, credit card details, medical records, home addresses) that must not be ingested into training runs or transmitted to external LLM APIs without strict compliance redaction. Mishandling PII leads to severe regulatory violations under GDPR, HIPAA, and CCPA.  
  → See [06-production/01-guardrails-and-security/05-pii-detection.md](../06-production/01-guardrails-and-security/05-pii-detection.md)

- **Presidio**: Microsoft's open-source SDK and service for detecting and anonymizing PII in text using customizable pattern matching, rule-based analyzers, and named entity recognition (NER) models. Deploying Presidio as an ingress gateway ensures sensitive entity redaction before text payloads hit vector databases or third-party LLM providers.  
  → See [06-production/01-guardrails-and-security/05-pii-detection.md](../06-production/01-guardrails-and-security/05-pii-detection.md)
